# Fix: Second Task Not Starting After First Task Completes

## Root Cause Analysis

After thorough investigation of the backend (`grizon-ai-backend-2-main/Brain/modules/chat/service.py`) and frontend (`Grizon-AI-Frontend-v2/brain/components/BrainMessages.tsx`), here are the issues:

### Issue 1: Missing `task_started` Event Handler (Frontend)
- **Backend** emits `task_started` events at `service.py:703` before each task begins execution
- **v2 Frontend** does NOT handle `task_started` events — only the newer `v2-api-2` frontend handles them at `BrainMessages.tsx:1635`
- Without this handler, the frontend never knows when a new task starts, so it can't show "executing" status for the next task

### Issue 2: Missing `task_failed` Event Handler (Frontend)  
- **Backend** emits `task_failed` events at `service.py:784` when a task times out or errors
- **Neither frontend** handles `task_failed` in the main SSE event loop
- If Task 2 fails (timeout after 480s or LLM error), the frontend silently shows it as "pending" forever

### Issue 3: `execute_sandbox` Events Don't Always Carry Updated Plan
- The builder's `_emit()` method yields `execute_sandbox` events with `activities` and `progress_msg` but **not** with the updated `plan` or `current_task_index`
- The streaming loop at `service.py:741-742` adds `plan` and `current_task_index` to these events
- But the first `execute_sandbox` event (task_started activity) gets `current_task_index = index` (current task), not `index + 1`
- The frontend's `mergeTodosFromPlan()` uses `activeIndex` to determine which task is "executing"
- If the plan in the event doesn't have updated `status` fields (because the builder hasn't finished yet), the frontend may show incorrect status

### Issue 4: Builder Agent May Be Silently Failing
- The builder's `_run_agent_loop()` catches ALL exceptions and returns a fallback message
- The `execute()` method catches timeouts and errors, marking them as "completed" (not "failed")
- This means the backend continues to the next task, but the frontend may not receive the updated state

## Fix Plan

### Fix 1: Add `task_started` Event Handler to v2 Frontend
**File:** `Grizon-AI-Frontend-v2/brain/components/BrainMessages.tsx`

Add handler around line 1259 (after the `execute_sandbox` handler):
```typescript
// --- Task Started (live progress before builder begins) ---
if (event.task_started) {
    const ts = event.task_started;
    const taskIndex = ts.current_task_index as number | undefined;
    const totalTasks = ts.total_tasks as number | undefined;
    const taskLabel = ts.task_label as string || '';
    const planFromTs = ts.plan as BuildTodoItem[] | undefined;

    if (Array.isArray(planFromTs) && planFromTs.length > 0) {
        currentTodoList = planFromTs;
        applyPlanToTodos(planFromTs, {
            activeIndex: taskIndex ?? 0,
            buildPhase: 'building',
        });
    }

    if (typeof taskIndex === 'number' && typeof totalTasks === 'number') {
        chunkUpdate = `🔄 Task ${taskIndex + 1}/${totalTasks}: ${taskLabel}`;
    }
}
```

### Fix 2: Add `task_failed` Event Handler to v2 Frontend
**File:** `Grizon-AI-Frontend-v2/brain/components/BrainMessages.tsx`

Add handler after the `task_started` handler:
```typescript
// --- Task Failed ---
if (event.task_failed) {
    const tf = event.task_failed;
    const failedIndex = tf.current_task_index as number | undefined;
    const reason = tf.reason as string || 'Task failed';
    const planFromFailed = tf.plan as BuildTodoItem[] | undefined;

    if (Array.isArray(planFromFailed) && planFromFailed.length > 0) {
        currentTodoList = planFromFailed;
        applyPlanToTodos(planFromFailed, {
            activeIndex: typeof failedIndex === 'number' ? failedIndex + 1 : undefined,
            buildPhase: 'building',
        });
    }

    chunkUpdate = `⚠️ Task failed: ${reason}`;
    appendBuildActivities([{
        id: `act-fail-${Date.now()}`,
        type: 'task_failed',
        label: reason,
        timestamp: Date.now(),
        status: 'failed',
    }]);
}
```

### Fix 3: Ensure `execute_sandbox` Events Always Carry Updated Plan Status
**File:** `grizon-ai-backend-2-main/Brain/modules/chat/service.py`

In the inner while loop (around line 739-743), ensure the plan's task statuses are synced before yielding:

```python
if ev.get("execute_sandbox"):
    exe = ev["execute_sandbox"]
    # Sync plan statuses from state before sending to frontend
    for i, t in enumerate(plan):
        if i < state.get("current_task_index", 0) and t.get("status") != "failed":
            t["status"] = "completed"
    exe["plan"] = plan
    exe["current_task_index"] = state.get("current_task_index", index + 1)
    yield f"data: {json.dumps({'execute_sandbox': _sanitize_for_json(exe)})}\n\n"
```

### Fix 4: Add Debug Logging to Backend Phase 2 Loop
**File:** `grizon-ai-backend-2-main/Brain/modules/chat/service.py`

Add logging at the start of each outer while loop iteration:

```python
while True:
    index = state.get("current_task_index", 0)
    print(f"DEBUG: Phase 2 — Task {index+1}/{len(plan)}: {plan[index].get('label', 'unknown') if index < len(plan) else 'DONE'}", flush=True)
    if index >= len(plan):
        break
```

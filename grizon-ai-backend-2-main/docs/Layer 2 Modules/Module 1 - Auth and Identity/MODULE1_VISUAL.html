Refresh Rotation & Reuse Detection
Each refresh rotates the token (sliding 30-day window). If a previously-rotated token is ever presented again → entire family_id is killed.
Login
issue T₁
family_id = F
→
Refresh
T₁ revoked
issue T₂ (family F)
→
Refresh
T₂ revoked
issue T₃ (family F)
→
⚠ T₁ presented again
REUSE DETECTED
→
Family F revoked
all access JTIs blacklisted
user must re-login
